## grok の大型 pack 欠席（argv 上限）を解消

取り込んだ改善メモの中で最頻の再発だった、`run_grok.sh` の argv 渡し問題に対処した。

### 症状と原因

`run_grok.sh` は CLI 経路で `grok -p "$PROMPT"` と **argv** でプロンプトを渡していた。
Linux の単一引数長の上限（`MAX_ARG_STRLEN` ≒ 128KB。`ARG_MAX` 2MB とは別物）を超えると
exec 自体が `Argument list too long` で失敗し、**grok だけが無言で空応答**になる。
実装レビュー型の大型 pack（148〜238KB）で4回再発していた
（IMPROVEMENTS 2026-07-25 ×2 / 07-30 / 08-05）。codex/gemini/claude は元から stdin 渡しで無傷。

再現も取った。248KB のプロンプトで `grok -p "$(cat big.md)"` → `argument list too long: timeout`。

### 採った手段: `--prompt-file`

Grok Build CLI の `--help` を確認したところ **`--prompt-file <PATH>`（Single-turn prompt
from a file）** があった。IMPROVEMENTS の案は「空 WORK_DIR に prompt.md を置いて
『このファイルを読んで回答せよ』と指示する」だったが、それはエージェントの読み取り挙動に
依存する。`--prompt-file` は CLI 自身がファイルを読んで単発プロンプトにするので、より直接的。

実機で確認:
- 248KB の `--prompt-file` → 期待どおりの回答（`BIGPONG`）を stdout に返す
- `run_grok.sh` 経由の E2E（ガード前置込み・248KB）も成功

プロンプトファイルは **WORK_DIR の外**（別 `mktemp -d`）に置いた。空 CWD で隔離している
意図を壊さないため（CWD に置くと「読めるファイルがある」状態になる）。
副次的に、argv 経由で実行中 `ps` にプロンプト全文が見える問題も消えた。

### 併せて入れたもの

1. **旧 CLI 向けフォールバックの明示エラー化**: `--prompt-file` 非対応の CLI では従来どおり
   `-p` に落ちるが、`QUORUM_MAX_ARGV_BYTES`（既定 120000）を超えたら
   `invalid_response:argv-too-long` を stderr に出して **exit 4**。無言の空応答にしない。
2. **`check_answer.sh` に第2引数 stderr**: 空応答のとき stderr に
   `Argument list too long` / `argv-too-long` があれば `invalid_response:argv-too-long` と
   名指しする。従来は `empty` としか出ず、原因特定に `.err` を人が読む必要があった。
3. **SKILL の回収手順で stderr を保存**: `run_<name>.sh 2>"$RUN_DIR/answer_<label>.err"`。
   空応答の原因は stderr にしか出ないため。Claude版・Codex版の両方に反映。
4. **run_*.sh 規約に明記**: 「プロンプトを argv に展開しない（stdin かファイル渡し）」を
   SKILL のバックエンド規約と README「パネリストを足す」の 4 項目目に追加。
