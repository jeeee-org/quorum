### 処置（ユーザー選択: grok 対策 A+B+C／refuter は D のみ）

1. **`run_grok.sh` にメタ応答リトライ**（A）: CLI 経路を `attempt()` に切り出し、
   **正常終了かつ回答が `QUORUM_MIN_ANSWER_BYTES`（既定 500）未満なら 1 回だけ投げ直す**
   （`QUORUM_GROK_RETRY=0` で無効）。再投入時だけ「直前の応答は作業予告で無効。最終回答を
   全文書き切れ」を後置。timeout(124)・argv 上限(4) では投げ直さない（同じ結果になり待ち時間が
   倍になるだけ）。回答は**長い方を採る**ので、再投入が更に短くても初回を失わない。
   回復しなければ stderr に `invalid_response:meta-only` を出すが、**回答自体はそのまま返す**
   （「自動棄却しない」方針は維持）。最悪レイテンシが `QUORUM_TIMEOUT` の 2 倍になる点は
   スクリプト冒頭と README に明記。
2. **連続 `invalid_response` の警告**（B）: `check_answer.sh --backend <name>` を追加し、
   連続回数を `$QUORUM_STATE_DIR/invalid.tsv`（`<backend>\t<連続回数>\t<最後にokだった時刻>`）へ
   記録。既定 2 回連続で stderr 警告（`QUORUM_INVALID_WARN`、0 で無効）。実質回答が 1 回返れば 0 に戻る。
   判定ロジックは一切変えず、出力経路を `emit()` に集約しただけ。
   **`absence.tsv` と同居させなかった**のが要点——`--check` は通るため absence 側は毎回 0 に
   リセットされ、同じファイルに乗せると永久に警告が出ない。
3. **補完分岐**（C）: 両 SKILL の step 2 に「`invalid_response` の枠はネイティブ枠で 1 回だけ
   補完し、`opus#N（grok 枠の補完）` として mapping.txt と監査証跡に明示。補完しない判断をした
   時も**パネルが N 体→M 体に縮んだ事実を書く**」を追加。幅の黙った縮退を防ぐ。
4. **judge_rubric に「証跡の所在 vs 転記」**（D）: 接地の非対称の隣に節を新設。主キー付きポインタは
   原本から再導出できるが pack 内テキストは自身から真正性を再導出できない／ただし照会手段の無い
   審査員にはポインタが届かないので**パネル構成の非対称として扱う**／pack-only を外すのではなく
   実環境アクセスを持つ枠と併存させる。あわせて「judge 自身が確かめる」表に
   **pack-only が「証跡が無い＝未証明」型を出した時**の行を追加（辿って確認 → 芯が残るなら
   棄却せず鋭い形へ翻訳）。
