### 実装

#### 1. 非対話実行に効く CLI オプション（commit 3a18c40）

- `run_grok.sh`: `--help` を1回 probe して `--no-plan` / `--no-subagents` があれば渡す。旧 CLI では渡さないので壊れない（`--prompt-file` と同じ判定方式）
  - **`--no-subagents` はメモに無かった追加の収穫**。`panelist_guard.txt` の「fan-out・サブエージェント禁止」を CLI 側でも機械的に担保でき、`run_codex.sh` の `--disable multi_agent` と対になる
- モデルは既定で指定しない方針を明文化（`GROK_MODEL` 未設定なら `-m` を渡さず CLI 既定に委ねる＝世代交代に自動追随）。**API フォールバック経路だけ `grok-4.5` 固定で置き去りになっていた**ので `grok-4.6` へ
- `run_*.sh --version` 規約を4本（grok/codex/gemini/claude）に追加
- `detect_panel.sh`: 参加 backend の版を `versions.tsv` に記録し、変化したら stderr で知らせる（`QUORUM_VERSION_WATCH=0` で無効）。初回・無変化は黙る

**probe の落とし穴**: `--version` 未対応の run スクリプトは引数を無視して `cat` で stdin を読みに行くので、**`</dev/null` で塞がないと probe が固まる**。テストで担保した（`--version` を実装していない mock で timeout しないこと）。

#### 2. check_answer の内容ベース判定（commit 6804601）

バイト数だけの検査は「閾値を超えた作業予告」を素通しし、実際に 588B の予告が `ok` を通り抜けていた。**閾値を上げる対処は採れない**——実 CLI に「1+1は？」を投げると `2` の1バイト回答が返る（正当な短答は実在する、という実測が取れた）。

| 判定 | exit | 内容 |
|---|---|---|
| `missing_expected:<語>` | 3 | `--expect <語>`（繰り返し可）。**OR 判定**——全語必須だと章立ての違いで落ちる |
| `plan_only` | 3 | 構造マーカー皆無 **かつ** 全行が予告文。`QUORUM_PLAN_ONLY_MAX_BYTES`（既定3000）以下のみ |
| `truncated_suspect:*` | **4** | `unclosed_fence` / `heading` / `midsentence` |

- **`truncated_suspect` を exit 4 の別系統にした理由**: `invalid_response`（exit 3）にすると SKILL 側の「ネイティブ枠で1回だけ補完」が発火し、**末尾が欠けただけの有効な回答を捨てる**誘導になる。連続 invalid カウンタにも数えない（backend は回答している）
- **`midsentence` は「句点で終わらない」ではなく「接続助詞・読点で終わる」で判定**。前者だと体言止めの箇条書き（「- 出典必須」）を大量に誤検知する。実例の「書いていないと」は `と` で終わるので拾える
- 連続警告から「恒久故障の疑い」の断定を外し、「恒久故障と断定せず、次回もパネルの枠は残すこと」を明記

**既存テストが1件落ちた**: 短文の題材に「これから確認します。」を使っており、閾値を下げると `plan_only` に当たった。これは**新機能が正しく発火した**結果なので、題材を「答えは 42 です。」に差し替え、代わりに「閾値を下げても作業予告は plan_only で落ちる」を新しい検査として追加した（穴が塞がったことの直接の証拠）。

#### 3. install.sh の Codex 配置任意化（commit 73dd83d）

`QUORUM_INSTALL_CODEX=0` / `--no-codex`。**既存の配置は自動削除しない**——env 1つでユーザーのファイルを削るのは危険なので、残存と `rm -rf` の手順を stderr で知らせるに留めた。
