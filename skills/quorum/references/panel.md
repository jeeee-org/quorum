# なぜ「独立並列」なのか

## 多様性は演出せず収穫する

役割（ペルソナ）を割り当てて多様性を作る方式（「あなたは批評家」「あなたは楽観派」）は、中身の伴わない見せかけの多様性になりやすい。

本スキルは逆に、**同じプロンプトを互いに見えない状態で独立に走らせる**。それだけで各回答者は異なる推論経路・異なるツール呼び出し・異なる参照ソースに分岐する。この「自然なブレ」を統合する方が、作り込んだ多様性より良い結果になる。

## 同一モデルの2回でも効く

別モデルが無くても成立する。**ホストの同じネイティブモデルを2回コールドに走らせて統合する**だけでも、単発の取りこぼしを補える。Claude Codeでは opus、Codexでは `codex-native` の独立サブエージェントが補完枠になる。異種モデルは多様性をさらに広げるための上乗せ。

## 欠けた枠はホストのネイティブ実行で補完する（バックフィル）

この性質を使い、**目標パネル数（既定3）を、まず opt-in された利用可能な異種backend、足りなければホストのネイティブ実行で埋める**。外部backend（codex/grok/gemini/外部claude）は**すべて既定オフ**なので、何も有効化しなければ Claude Codeホストは **opus×3**、Codexホストは **codex-native×3**。`QUORUM_ENABLE_*=1` で有効化すると、Claude=**opus / codex / grok**、Codex=**codex-native / claude / grok** の3ベンダー幅になる。現在ホストと同名の外部runnerは除外し、CLIのネストとquorum再帰を防ぐ。別モデルが入る枠ほど多様性は高いが、同族補完でも偶発的な取りこぼしを減らせる。補完は `detect_panel.sh` が `QUORUM_HOST` と `QUORUM_PANEL_SIZE` に従って行い、特定バックエンドの増員・固定は `QUORUM_PANEL` の明示指定で行う。

**opus 枠の fable 差し替え（`QUORUM_NATIVE=fable`）はユーザーの呼びかけ時のみ**。judge と同格のモデルをパネル（幅）に使うのは「深さは judge・幅は安価なモデル」の基本配置に反し費用対効果が悪いが、最重要の1問で幅の質も上げたい局面のための明示オプション。補完で fable を増殖させることはない（補完チェーンに fable は入れない）。

## judge は最強モデルに座らせる（深さは judge・幅はパネル）

融合の品質上限は judge の突き合わせ能力で決まる——矛盾の裁定・重みづけ・盲点の補完は judge の知性がボトルネックになる。∴ **judge にはセッションで使える最も賢いモデルを座らせ、パネリストはネイティブ独立実行＋異種ベンダーで幅を稼ぐ**のが基本配置。

同一モデルの複数独立実行が拾えるのは「たまたまの取りこぼし」であって、モデル自身の系統的な盲点は N 体走らせても全員が同じ場所で転ぶ。**メインホストとは別ベンダーのモデルは訓練データも検索経路も癖も違うため、この相関しない誤りを相殺できる**——これはメインのモデルがどれだけ賢くなっても消えない、本スキルの中核価値。

## ブラインドを守る

パネリストどうしに中間結果を見せない。見せ合うと互いに引きずられ（アンカリング）、独立性＝多様性の源泉が潰れる。突き合わせは最後に judge が一括で行う。

## リポを読める枠には、書き込みの可否と作業場所を必ず書く

パネリストを「回答を返すだけの存在」として扱うと事故が起きる。**リポを読める枠（opus など）は書き込みもできる**——2026-08-17 に、「思いついた反例はプロトタイプへ当てて実測してから書け」と指示した opus 枠が、プロトタイプではなく**本番の実装ファイルを直接書き換えて**試験を流していた。こちらは別の測定をして初めて気づいた。並列セッションがいれば、汚れたコードを本物として読む事故になっていた。

∴ リポを読める枠へ渡す指示には、次の3点を**毎回明示する**（指示の書き手が思い出す前提にしない）：

1. **読み取り専用でよいならその旨を書く**。既定は読み取り専用。
2. **実験のために書き換えが要るなら、作業場所を渡す**。元 clone は触らせない。
3. **渡す場所は、判定を待つ間だれも編集しない場所にする**。

3 が抜けると、worktree を渡しても事故る。同日の再発では**渡した worktree が judge 自身の作業場所**で、レビュー中に judge が次の工程を進めて未 commit の変更を持っていた。パネリストの「変異を当てたら元に戻す」は**パネリストが読んだ時点のコピー**へ戻すので、judge の未 commit 変更ごと巻き戻る。しかも試験も一緒に巻き戻るため**赤にならず気づけない**。

- 本筋 = **レビュー専用の worktree / 一時コピーを切って渡す**（並列で回すループでは「判定中は触らない」を人間側で守れない）。
- 保険 = **fan-out 後の回収時に `git status` で作業ツリーの汚れを確認する**（SKILL step 2）。再発時はこれで気づけた。

## リポ実読の枠が2つ取れるときは、指示を分ける

欠席の補完で「リポを読める枠」が2体になることがある（本来枠＋補完枠）。**同じ指示を2体へ投げるより、読み方を分けたほうが収穫が増える**。

2026-08-18 の実装レビューでは、本来枠が「出口検査が実機の行に掛かっていない」（構造の穴）を、補完枠が「打ち間違いが前の目印へ黙って連結され、否定の目印だと常に緑になる」（入力の迂回路）を出し、**重なりはほぼ無かった**。「資料だけの体 vs リポを読める体」という既知の非対称の**内側に、さらに読み方の分岐がある**。

- 一方へ: **実行経路と契約の突き合わせ**（誰が何を保証するか・構造の穴）
- もう一方へ: **入力の総当たり**（書き損じ・全角半角・装飾・エスケープ・境界値）

**欠席の補完は、幅を戻すだけでなく指示を変える機会**として使う。
